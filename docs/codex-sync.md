# 让 AI 安装和更新 Codex 全局规则

将下面这段话发送给目标设备上具有本地文件读写能力的 Codex 或其他 AI。首次安装和后续更新均可使用。

```text
请从 https://github.com/Lidong1793/agent-rules 获取 main 分支最新的
platforms/codex/AGENTS.md，并用它更新本机的 Codex 全局规则。

请直接完成以下操作：
1. 确认本机 Codex 全局目录。设置了 CODEX_HOME 时使用该目录，否则使用当前用户的 ~/.codex。请解析当前操作系统的真实用户目录。
2. 下载仓库中的规则文件，确认下载成功且内容为预期的 Markdown 规则。记录采用的提交 SHA。
3. 读取本机现有 AGENTS.md 和 AGENTS.override.md。修改前，将存在的文件备份为带时间戳的文件，保存在本机。
4. 以仓库版本更新同名规则章节，保留本机额外的个人规则。个人规则与仓库规则存在实质冲突时，列出具体冲突并让我选择后再写入。首次安装且本机没有规则时，直接使用仓库版本。
5. 如果全局目录存在非空 AGENTS.override.md，将合并后的规则写入该优先加载文件；同时说明实际生效路径。其余情况下写入 AGENTS.md。
6. 使用 UTF-8 保存并重新读取文件，检查内容完整、同名章节已更新且没有重复。内容相同时跳过写入。
7. 告诉我来源提交、实际生效文件路径、备份位置、更新摘要，以及新建 Codex 会话后验证规则的方法。

本次操作范围是全局规则文件。规则中提到的配置文件和 profile 请按目标设备现状说明；修改 config.toml、创建 astra-double 配置或配置定时同步，需要我另行提出要求。
```

## 日常更新

仓库规则修改后，再向 AI 发送同一段提示词即可。每次同步都获取最新版本，并重新检查本机已有的个人规则。

如果使用本地克隆，在工作区干净时运行 `git pull --ff-only` 更新。存在本地改动时，先保留改动并说明具体差异；可以使用独立临时目录获取远端规则，再完成合并。

## 验证

完成后新建 Codex 会话，发送：

```text
请总结当前加载的全局规则，重点说明：
1. Astra 为简单任务启动子代理前需要做什么？
2. 子代理的模型和推理强度由谁决定？
3. GitHub 提交与 CI 的规则是什么？
```

期望结果：简单任务默认由 Astra 自行完成；使用子代理前说明理由和分工并征得用户明确同意；子代理模型和推理强度由主代理按任务需要及工具支持决定；CI 遵循全局规则中的触发条件。

## 向仓库反馈改进

朋友可以 fork 此公开仓库，修改规则并提交 Pull Request。仓库维护者审查并合并后，其他设备再次同步即可获取更新。
